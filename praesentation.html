/// DIE IDEE

API-Endpunkte fallen aus. Aber wann? Und wie lange?
Und vor allem: Wer merkt es zuerst?

ACM ist ein Monitoring-Tool, das genau das im Blick behält:
Definiere Endpunkte, wähle den Check-Typ, setze Intervalle --

Problem

  • APIs fallen unangekündigt aus
  • Keine Übersicht über mehrere Services
  • Manuelles Prüfen ist nervig
  • Keine Historie bei Ausfällen

Lösung

  • Automatisches Echtzeit-Monitoring
  • Dashboard mit Live-Status und Logs
  • HTTP, TCP und ICMP aus einer Hand
  • PostgreSQL-DB für Logs + User + Endpunkte

/// TECH-STACK

Backend

  • 🦀 Rust + Axum > sicher, schnell, kein Garbage Collector, geringer Speicherverbrauch
  • ⚡ Tokio > asynchron, viele parallele Checks gleichzeitig
  • 🐘 PostgreSQL > relational, zuverlässig, JSON-Abfragen möglich
  • 🔧 sqlx > Compile-Time-Prüfungen, keine Laufzeitfehler

Frontend

  • ⚛️ React 19 > Standard, riesiges Ökosystem, einfach teamfähig
  • 🎨 Tailwind v4 > kein CSS, Utility-First-Ansatz, schnelle Iterationen

Infra

  • 🔄 Nginx > Reverse-Proxy, Same-Origin-Prinzip, kein CORS mehr nötig
  • ☁️ AWS > EC2 günstig, S3 Static-Hosting, RDS managed Datenbank
  • 📦 Docker > PostgreSQL-Container, Entwicklungsumgebung reproduzierbar

/// FEATURES

Monitoring

  • HTTP -- GET-Request, 2xx = Up
  • TCP -- Port offen? Verbindung da?
  • ICMP -- Ping, ob der Host lebt
  • Individuelle Intervalle pro Endpunkt

Dashboard

  • Live-Status mit Status-LED
  • Sparkline-Chart der letzten 30 Checks
  • Killswitch pro Endpunkt + MAIN_SWITCH
  • Uptime-Dauer auf einen Blick
  • Detaillierte Logs mit Filter

Accounts

  • Registrierung + Login
  • Passwort-Hashing via bcrypt
  • Session-Token (UUIDv4)
  • Passwort / Email ändern

UI

  • 3 Themes: Lava Red / Hacker Green / Void Purple
  • Responsive, brutalistisch, futuristisch

/// API-ROUTES

14 Endpunkte -- 3 öffentlich, 11 mit Bearer-Token geschützt

Öffentlich

  • Healthcheck, Login, Registrierung

Geschützt

  • Dashboard, Nutzerverwaltung
  • Endpunkte: anlegen, ändern, löschen
  • Intervall setzen, Logs abrufen

Monitoring-Loop

  • Hintergrund-Task (tokio::spawn)
  • Prüft alle Endpunkte im Intervall-Takt
  • Schreibt Status in die Log-Tabelle

Authentifizierung

  • bcrypt-Passwort-Hashing
  • UUIDv4-Session-Token (in Memory)
  • Authorization: Bearer-Header

/// MONITORING-LOOP

So laufen die Checks im Hintergrund
graph TD
    START[Loop] --> ABFR[SELECT due]
    ABFR --> PARALLEL[join_all]
    PARALLEL --> CHK{check_type}
    CHK --> H_REQ[HTTP]
    CHK --> T_REQ[TCP]
    CHK --> I_REQ[ICMP]
    H_REQ --> UP[up]
    H_REQ --> DOWN[down]
    T_REQ --> UP
    T_REQ --> DOWN
    I_REQ --> UP
    I_REQ --> DOWN
    UP --> WRITE[INSERT log]
    DOWN --> WRITE
    WRITE --> SLEEP[sleep]
    SLEEP --> START
